Help / Domain model
对象关系
SpecWire 以 Workspace 隔离配置，以 Connection 承载两端项目和多个 Integration Flow。

      

        
先记住一个事实
项目不是独立的 SpecWire 配置对象
GitLab 源项目和 Multica 目标项目是外部系统中的项目引用。它们通过 Connection 被纳入 Workspace；创建或接入项目的入口是“连接管理 → 新建 Connection”。
GitLab 项目、Multica 项目页面是 Connection 的查询视图，不负责单独创建项目。

        
运行闭环
配置、编排、执行是三层
配置端点与凭据→建立 Connection→发布 Flow→产生 Execution
Onboarding 准备项目、资源和共享 Hook；只有发布带入口行为的 Flow 后，事件才会进入执行链路。

Where to configure
各对象在哪里配置
实例实例配置 → 添加实例
发现 / Group 凭据实例配置或 Connection onboarding
项目映射连接管理 → 新建 Connection
连接器行为 / 数据模型配置 → 集成能力
FlowConnection 详情 → 集成流 → 打开 Builder
执行执行记录或 Connection 详情 → 执行记录

        
Avoid confusion
三个容易混淆的概念
实例 ≠ 连接器节点
实例是 Workspace 的控制端点；Flow 节点只是行为类型加参数。
Connection ≠ Flow
Connection 保存项目映射和授权范围；Flow 描述事件如何处理。
Hook ≠ Execution
Hook 是事件入口和路由；Execution 是某次 Flow 运行的持久化记录。

      

    

  





添加实例
创建 Workspace-owned 的 Provider endpoint；凭据在保存后单独绑定。


注册连接器行为
只登记服务端已经部署并 allowlisted 的 adapter metadata；这里不能上传脚本、二进制或任意 HTTP 定义。
选项来自服务端部署的 adapter allowlist。
多个能力用逗号分隔，至少填写一个。


新建 DataModel
DataModel 是节点端口之间的版本化数据契约。已发布版本不可修改；创建新版本后，Flow 需要显式选择新版本。
多个字段用逗号或换行分隔。
允许未列入 schema 的 provider 扩展字段保留在模型中。
创建新版本不会改变已发布 FlowVersion；现有 Flow 仍固定引用原模型版本。




登录 SpecWire
使用本地 provider 登录；外部 OAuth/OIDC 可由部署配置启用。
